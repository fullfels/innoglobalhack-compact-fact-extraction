**10 первых звонков официального val, без SFT/LoRA. Не полный baseline по 383 звонкам и не результат обученной модели.** Это частичное свидетельство для T07/T08; задачи не считаются закрытыми.

## Качество на одинаковых 10 звонках

В эталоне 54 факта и 16 текущих состояний. Использован неизменённый официальный evaluator. Обе сохранённые таблицы метрик воспроизведены локально.

| Метрика | Исходная Qwen3.5 | Ответы базы МТС на тех же звонках |
|---|---:|---:|
| Fact precision | 0.2500 | 0.1613 |
| Fact recall | 0.0370 | 0.1852 |
| Temporal recall | 0.0000 | 0.4000 |
| State accuracy | 0.0625 | 0.3750 |
| Grounding turn | 0.5000 | 0.7000 |

Совпали 2 из 8 принятых предсказаний; полнота — 2/54. Precision выше базы не означает превосходство: большинство фактов пропущено. В выданном скрипте temporal recall считается среди сопоставленных фактов; здесь их только два, и даты обоих не прошли проверку.

## Что выявлено

- Структурно приняты **8/10** ответов; это не 80% правильных фактов.
- **Два ответа отклонены из-за speaker/source mismatch**. В текущем offline-пробнике ошибки явно записаны в summary, а в predictions учитываются пустыми facts. Это соглашение измерения сбоя, не успешная пустая выдача и не поведение serving API.
- Все десять сырых ответов содержат ровно один факт; все valid_from равны started_at. Ограничения входа/ответа не сработали.
- В просмотренном примере будущая договорённость записана как service_state, с датой звонка вместо согласованного срока.
- Полные raw-ответы и транскрипты сохранены в приватном архиве результатов, не в Git. Здесь опубликованы только компактные результаты и [наблюдения](observations.json).

## Предварительные ресурсы

- Средняя задержка **5.564375 с** — только по восьми принятым ответам.
- p50 **5.5371 с**, p95 **6.705 с**; выборка мала.
- Сумма времени всех десяти попыток **56.081 с**.
- Пик CUDA **allocated** — **2395.38 MiB**; это не общая занятость VRAM процесса.
- Из задержки исключены загрузка и прогрев; применена CUDA synchronization.

Это диагностический warmed run, не полный CPU/GPU benchmark и не доказательство экономии относительно учителя. Один факт на ответ не позволяет объявить высокую производительность полноценного извлечения. Ресурсы учителя неизвестны.

## Файлы и воспроизведение

`source/` содержит **точные архивные версии** predict.py, common.py, prompt.txt и requirements из исполненного Colab-пакета; их хеши сверены с manifest. Это исторический standalone runner, не serving bridge проекта и не новая общая схема. Он не подключён к API и не меняет `src/contracts`/pipeline. Целевые интерфейсы интеграции остаются в [INTEGRATION_HANDOFF](../../../docs/INTEGRATION_HANDOFF.md).

Блокнот: [MTS_02_Qwen35_Check.ipynb](notebooks/MTS_02_Qwen35_Check.ipynb). Для повторения загрузить в него исходный приватный `mts_qwen35_probe.zip`, полученный у ML; архив содержит корпус организаторов и поэтому хранится вне Git. Его SHA256 и хеш архива результатов находятся в [provenance.json](provenance.json). Доступ к данным и весам следует [data/README](../../../data/README.md) и [artifacts/README](../../../artifacts/README.md).

Чтобы проверить сохранённые метрики без GPU и ML-библиотек, из этой папки:

```bash
python verify_metrics.py --data /path/to/CaseData
```

Скрипт требует официальный val, baseline_pred и case_metrics.py отдельно, сверяет их SHA256 и выбирает ровно сохранённые 10 call_id. Корпус, gold/baseline-срезы, каталог, схема и evaluator не копируются в Git.

## Ограничения и следующий шаг

Изменились модель, prompt и parser по сравнению с прежним Qwen3-0.6B run. Изолированного сравнения архитектур пока нет. Выборка не репрезентативна; отдельные DE нормализаторы ещё не подключены, Case-SFT не выполнялся, CPU/INT8/INT4 и real Docker acceptance не проверялись.

Следующий шаг — pilot LoRA по T09 с групповой внутренней проверкой, loss masking, измерением памяти/ETA и reload адаптера. Полный DoD T08 (inner-dev и сопоставимая base), полная валидация, три режима и ресурсные gates остаются открытыми.
