# Только проверка +500 на 383 звонках

Откройте `MTS_12_Qwen06_Official383_Eval.ipynb` в Colab (Файл → Загрузить блокнот). Выберите GPU, предпочтительно A100. Запустите разделы 1 → 2 → 3. В разделе 2 загрузите только `mts_qwen06_official383.zip` (~40 МБ). Никакие старые обучающие ZIP не нужны. Раздел 4 — просмотр и повторное скачивание.

Здесь нет обучения. В ZIP находятся наш проверенный выбранный адаптер исходной +500, tokenizer, prompt/каталог, неизменённый официальный evaluator v2.1, все 383 официальных val-звонка и baseline для воспроизводимого сравнения. Обучающих JSONL нет. Инференс получает call_id, started_at и исходные turns, без gold facts; шумный текст сохраняется. Проверяются 383 звонка / 1845 эталонных фактов.

Настройки прежние: одна GPU, batch 1, FP16, greedy, thinking выключен, KV-cache включён, контекст 24576, выход до 2048 токенов, до 120 секунд на звонок. Адаптер не меняется; календарный эксперимент отключён как в выбранном export. База скачивается с закреплённой revision. Torch/CUDA не переустанавливаются; тренировка и квантованные режимы не запускаются.

Ориентир по прежним ~31 секунде на звонок — около 3 часов 20 минут генерации, плюс подготовка и подсчёт. Это оценка, не обещание. GPU и длина диалогов влияют на время. По первым звонкам печатается remaining_est_min. Полный отдельный бюджет — до 4 часов с подключения Drive, абсолютная остановка не позже 16 ноября 07:00 МСК. Старый пятитичасовой бюджет обучения не сбрасывается и не меняется. До публикации кода в 08:00 должен остаться резерв.

Каждая законченная генерация записывается на Drive в RUN/official_val383/records. Повторный запуск того же RUN использует сохранённые записи, проверяя модель, входы и конфигурацию. Менять модель/GPU/версии в середине такого прогона запрещает проверка конфигурации; это обеспечивает сопоставимость. При восстановлении укажите тот же RUN в RESUME_RUN; не меняйте сохранённый бюджет. Дополнительная оценка при его исчерпании требует отдельного решения, автоматического продления нет.

В конце скачивается *_results.zip. Нужны final_report.json: complete=true, n_completed=383; predictions.jsonl; baseline_recomputed.json; official_val383/metrics.json, сырые записи и error_analysis. При обрыве можно скачать промежуточный ZIP; неполный набор обозначен PARTIAL и не считается доказательством порога. Ошибки генерации записываются как failed; пустой список для их штрафного учёта в evaluator не означает успешное извлечение.

Первый приоритет — полный FP16-прогон. Он даёт одну ресурсную точку и окончательные метрики на val, но сам по себе не закрывает три режима, сравнение с ресурсами baseline, полный шумовой анализ или весь комплект сдачи. Данная подготовка не подтверждает прохождение порогов и не заменяет запуск GPU.

Перед выпуском проверены происхождение весов, пакетные hashes, отсутствие gold в model input, неизменность реплик/evaluator, подсчёт baseline, сохранение/повторное использование записей, явный учёт failures, остановка по бюджету и код блокнота. Проверки управления выполнены с подставным движком; результатов GPU-оценки этого нового запуска здесь пока нет. Отчёт CPU-проверок находится рядом, отдельно от пакета.
