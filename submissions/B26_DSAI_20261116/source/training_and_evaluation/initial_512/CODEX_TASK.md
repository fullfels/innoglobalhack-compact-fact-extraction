# Codex участника №2: Qwen3-0.6B для МТС

Помоги участнику Innopolis Global Hack 2026 выполнить один реальный ограниченный LoRA-эксперимент. Прочитай `START_HERE.md`, `LOCAL_CHECKS.json` и manifest пакета. Локальные проверки выполнены, но GPU-обучение ещё не запускалось: его результаты нужно получить в Colab владельца.

Репозиторий: https://github.com/fullfels/innoglobalhack-compact-fact-extraction

Координатор отдельно работает с Qwen3.5-0.8B. Твой эксперимент не заменяет исторические результаты PR52–54. Срок команды — **15 ноября 2026, 23:59 МСК**; утро 16-го оставляем для презентации.

## Цель и формат

Вернуть исследовательский кандидат: base + adapter, tokenizer, настройки, проверку свежей загрузки, сырые ответы, predictions, метрики и ресурсы. При неудаче вернуть доступные артефакты и точную причину. Завершённое обучение не означает прохождения порогов МТС.

Модель извлекает факты из русских шумных разговоров, включая изменения состояний во времени. Она возвращает JSON, а не отвечает клиенту и не задаёт уточняющие вопросы. Объекты: услуга, устройство, заявка, клиент. Атрибуты: `service_state`, `tariff`, `ticket_status`, `action`, `agreement`. Авторитетный формат: `official_schema.md` и существующий `src/contracts/models.py`.

## Первый закреплённый запуск

| Настройка | Значение |
|---|---|
| Base | `Qwen/Qwen3-0.6B` |
| Revision | `c1899de289a04d12100db370d81485cdf75e47ca` |
| Loader | AutoModelForCausalLM, SDPA, без remote code |
| LoRA | Новая от base; r16, alpha32, dropout0 |
| Модули | q/k/v/o/gate/up/down в language layers, без embeddings/lm_head |
| Объём | Один проход, 512 звонков, 128 optimizer steps |
| Batch | Microbatch1, accumulation4, seed42 |
| Числа | FP16 base, FP32 обучаемые LoRA-матрицы, без 4-bit |
| Optimizer | AdamW, LR1e-4, warmup7, линейный decay, clip1.0 |
| Память | Gradient checkpointing, context16384, без truncation |
| Генерация | Thinking выключен, greedy, KV-cache, max_new_tokens1536 |
| Бюджет | До 4 часов optimizer loop с промежуточными проверками |

Загрузка и финальная оценка занимают дополнительное время. Это бюджет, а не обещание качества. LoRA от Qwen3.5-0.8B несовместима с этой базой.

Команда из корня payload:

```text
python -u -m ml.qwen.friend_qwen06 --root /content/mts_friend_qwen06 --out /content/mts_friend_runs/UNIQUE_RUN --precision float16 --learning-rate 0.0001 --budget-hours 4
```

Запускай `friend_qwen06`. Общий `ml.qwen.train` включён как библиотека функций и имеет старый main для 0.8B/32 примеров; этот main здесь не запускать.

## Выполнение

1. Загрузить блокнот в Colab, выбрать GPU и сохранить сведения о GPU, VRAM, CUDA и версиях. Аутентификацию выполняет владелец аккаунта.
2. Загрузить payload, проверить ZIP SHA и файлы. Выполнить `python verify_friend.py --tokenizer`: проверяются схема, роли, отсутствие утечки gold, сообщения train/inference, маски, EOS и длины.
3. Установить закреплённые requirements, сохранив CUDA PyTorch среды. Владелец включает `RUN_TRAINING=True` для единственного запуска. Обучение идёт в отдельном Python-процессе.
4. До optimizer loop проверить эквивалентность suffix-only loss обычному masked CE и backward самого длинного train без изменения весов. Сохранить ответы на первых четырёх фиксированных dev.
5. Первые три обновления должны иметь конечные градиенты и менять LoRA. При NaN/Inf остановиться до optimizer update.
6. Last сохраняется каждые 32 шага. На шагах 64/128 измеряется извлечение на тех же четырёх dev. Best выбирается по factF1, затем recall/state/time/grounding и числу failures. Один низкий teacher-forced loss не определяет best.
7. После loop сохранить last, заново загрузить base и выбранный адаптер, проверить logits. Оценить все 20dev и четыре train. Парные after4 берутся из сохранённых dev20 без повторной генерации. Сравнивать before4 именно с after4, а не с after20.
8. Скачать ZIP и передать команде. При ошибке сохранить failure.json, логи и checkpoint. Прежние результаты не перезаписывать.

## Корректность

В loss участвуют только правильный ответ и EOS; инструкция, каталог и разговор замаскированы `-100`. Накопление нормируется числом обучаемых токенов окна, а не примеров. Suffix-only logits экономят память; эквивалентность проверяется на реальной модели.

Общий bridge строго проверяет JSON, поля, даты и источник. Не переписывать speaker, не переносить turn_idx, не подставлять дату звонка вместо неизвестной исторической даты. Ошибка остаётся `status=failed, facts=null` в raw. Пустой список в evaluator-view означает ноль найденных фактов, а не успешный пустой ответ.

Raw extraction и Pipeline считаются раздельно: неподтверждённые agreement фильтруются до подключения DE. Не выставлять confirmed по одному слову «да». Нормализаторы и HTTP/Docker acceptance этим опытом не закрываются.

## Оценивание

Evaluator не менять: `evaluation/case_metrics.py`, SHA256 `dffec9b8b20c5a8a101a33a27b1672f2b6195f00ab60f021a1c14b31eeeacabd`. Особенности matcher не использовать для подгонки ответов.

```text
python -m ml.qwen.analyze_results --gold /content/mts_friend_qwen06/data/dev_20.jsonl --prediction-dir /content/mts_friend_runs/UNIQUE_RUN/after_dev20 --evaluator /content/mts_friend_qwen06/evaluation/case_metrics.py --output /content/mts_friend_runs/UNIQUE_RUN/dev_error_analysis.json
```

Показывать precision/recall, temporal/state, grounding, gold/predicted/matched counts и structural failures отдельно. Temporal recall здесь считается среди совпавших фактов: высокий score на одном совпадении не означает полноту истории.

Порог МТС: падение temporal и state не более 0.02 от baseline при сокращении параметров минимум 10× ИЛИ GPU-секунд минимум 5×. Падение temporal более 0.05 исключает решение. Опубликованы temporal0.4161/state0.3483, пересчёт evaluator даёт 0.4205/0.3194. Внутренние осторожные ориентиры команды —0.4005/0.3283; это не новые официальные требования. По dev20 финальный casepass не выставлять. Параметры и GPU-время большого baseline неизвестны: доказательство 10×/5× не выдумывать.

## При сбое и ограничения объёма

- Сохранить этап, причину, логи и checkpoint. Не тратить часы на ещё один отдельный 32-call overfit.
- Не обновлять весь PyTorch вслепую, не покупать GPU/тариф, не публиковать корпус, веса или токены.
- FP16 NaN/Inf требует остановки. FP32 возможен как явный новый эксперимент с новой папкой после решения команды; результаты не смешивать.
- При OOM сохранить длину и память. Не обрезать turns/labels и не исключать трудные звонки скрытно.
- `--recheck last` или `--recheck best` только оценивает адаптер. Точное возобновление optimizer не реализовано.
- Не расширять обучение до 3375 и не перебирать дополнительные LR/rank или модели без решения команды. Сначала вернуть результат одного прохода.
