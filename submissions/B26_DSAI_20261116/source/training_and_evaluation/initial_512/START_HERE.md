# Другу: один эксперимент Qwen3-0.6B для МТС

Весь пакет предназначен для передачи участнику команды, не для публичного GitHub. Данные — очищенный официальный корпус МТС v2. Это не прежний синтетический набор обращений про Android и 403.

## Что сделать

1. Распаковать внешний архив `MTS_FRIEND_QWEN06.zip` на компьютере.
2. Передать своему Codex файл `CODEX_TASK.md` и путь к распакованной папке. Репозиторий команды уже указан в задании; для первого запуска GitHub не нужен.
3. Открыть [Google Colab](https://colab.research.google.com/), выбрать «Файл → Загрузить блокнот» и загрузить `MTS_04_Qwen3_06B_Friend.ipynb`.
4. Выбрать среду выполнения с GPU. Выполнить ячейки по очереди. В первой ячейке загрузить **только `mts_friend_qwen06_payload.zip`** из этой папки.
5. Дождаться успешной проверки файлов, токенизатора и 512/20 выборок. Вывести сведения о GPU и установленных библиотеках.
6. В ячейке обучения установить `RUN_TRAINING = True` и выполнить **эту ячейку один раз**. По умолчанию флаг False: случайное «Выполнить всё» не начинает обучение.
7. После завершения скачать автоматически предложенный ZIP результатов. Если обучение закончилось ошибкой, скачать архив с failure/logs/checkpoints и передать его координатору. Не запускать всё заново до разбора ошибки.

## Что именно обучается

- Модель `Qwen/Qwen3-0.6B`, версия `c1899de289a04d12100db370d81485cdf75e47ca`.
- Новая LoRA r16/alpha32 от исходной предобученной модели. Адаптер от Qwen3.5-0.8B несовместим.
- 512 train /20inner-dev; случайный фиксированный выбор seed42 из готовых 3375/366. Train содержит 2460 фактов, dev103.
- Один проход:128 optimizer steps по 4 звонка, microbatch1. Только токены правильного ответа участвуют в loss; накопление нормируется числом этих токенов.
- FP16 для base, обучаемые LoRA-матрицы FP32, AdamW, LR1e-4, SDPA, thinkingoff. 4-битного обучения нет.
- Максимум 16384 токена контекста; текст и ответы не обрезаются. При переполнении — остановка с объяснением.
- Бюджет optimizer loop — до 4 часов, включая промежуточные проверки. Загрузка и финальная оценка могут занять дополнительное время. Это ограничение эксперимента, не обещание качества или времени.

## Проверка до и после

До обучения: первые 4 из фиксированного dev20. После: все 20dev и отдельно 4train для диагностики. Парные «до/после» сравниваются только на тех же 4dev-ID; после 4 берётся из сохранённых dev20 ответов без повторной генерации. Выбор best — по извлечению фактов на фиксированных 4inner-dev, не по одному teacher-forced loss. Это малый эксперимент, не итоговые проценты хакатона.

До optimizer loop выполняются проверка эквивалентности loss и backward самого длинного из 512train без изменения весов. Первые 3 реальных optimizer updates должны быть конечными и менять LoRA. Остановка при NaN/Inf, без скрытого пропуска шагов.

## Что вернуть команде

Один ZIP результата: best/last/export с адаптером и tokenizer, `experiment_report.json`, `training_config.json`, `training_log.json`, `loss_equivalence.json`, `long_call_probe.json`, `first_updates.json`, `reload_test.json`, исходные ответы и predictions. При неудаче — те же доступные файлы плюс`failure.json`. Блокнот автоматически добавляет исполненные исходники и manifest.

Написать фактические GPU, общее время, сколько звонков увидела модель, precision/recall, temporal/state, число совпавших фактов и структурных отказов. Валидный JSON сам по себе не означает правильные факты.

## Важные границы

- Официальный val383 и карантин 185 в пакет не включены. На проверочных 20 звонках не обучаться и gold во вход модели не подавать.
- Порог 0,02 относится к падению относительно baseline, не к «98%правильных ответов». Достижение официального порога по 20dev не подтверждается.
- Все результаты двух участников сравниваются на тех же 20ID. Основная Qwen3.5-0.8B остаётся отдельным кандидатом.
- Веса и корпус не публиковать в Git. Результаты передать своей команде.
- Дедлайн ML-пакета —15 ноября 2026,23:59 МСК. Утро 16-го оставляем для презентации и подготовки.

## Если ошибка или отключение

При отсутствии GPU обучение не начинается. При ошибке установки не обновлять вслепую весь PyTorch. При FP16 NaN/Inf сохранить неудачу; явный новый FP32-run возможен после согласования внутри команды, это другой эксперимент. При OOM не обрезать данные и не удалять трудные звонки скрытно. Повторный запуск в старую папку отвергается, чтобы не потерять доказательства.

Colab может удалить локальные файлы после отключения. Для сохранения промежуточных весов можно заранее включить `SAVE_TO_DRIVE=True` и самому подтвердить подключение своего GoogleDrive; это необязательно. Точное возобновление optimizer не реализовано: `--recheck` только загружает адаптер для оценки. Архив скачать обязательно.
