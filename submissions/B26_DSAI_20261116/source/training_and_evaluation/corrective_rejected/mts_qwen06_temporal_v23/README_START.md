# МТС · Qwen3-0.6B · корректирующее LoRA-дообучение v23

**Это настоящее продолжение обучения от вашего +500.** Первый эксперимент и его веса не перезаписываются. Результаты текущей отдельной проверки 16 звонков для подготовки этого пакета не нужны. Не запускайте два GPU-worker одновременно в одной Colab VM: дождитесь окончания/остановите прежнюю проверку перед ячейкой 4.

## Что обучаем

- База Qwen/Qwen3-0.6B, revision c1899de289a04d12100db370d81485cdf75e47ca.
- Начальный LoRA-адаптер: последняя v21-версия +500, SHA256 577bc8184877de05386244791bee2ecaeb5dd894e86df749cd31ed270dbab98b.
- 1024 примера: 512 реальных звонков с источниковой поддержкой хотя бы одной даты +256 обычных реальных звонков +256 синтетических диалогов (128 семей, каждая в исходном и усиленно зашумлённом варианте).
- Все 768 реальных звонков взяты только из подготовленного официального train v3. Их turns и исходные gold-даты не переписаны. Факты не удалены. Вход не содержит gold facts, object.id, confirmed, обучающих меток времени или признака происхождения.
- Сомнительные реальные timestamps не получают loss на неизвестных символах. При доказанном дне без доказанного часа обучается день, а неизвестные часы маскируются. Проверенные временные токены имеют вес2, остальные ответные токены —1. Это отдельная проверяемая гипотеза, её польза не гарантирована.
- Один проход: максимум256 обновлений, accumulation4. Каждый update содержит2 реальных примера с датами,1 обычный реальный и1 синтетический. LR1e-5, warmup8, линейное снижение, clip0.5, база FP16/адаптер FP32. Обучаются только существующие10092544 параметра LoRA.

## Проверки и защита от ухудшения

До и после применяется одна и та же новая версия pipeline. Выбор опирается на **24 реальных внутренних dev-звонка**, отдельно проверяются8 синтетических стресс-примеров. Затем используется страховочный набор16 других реальных +8 других синтетических. Все аккаунты/синтетические семьи разделены; официальные383 val не используются для выбора.

Новая версия допускается только при сохранении real recall/state/temporal, количества совпавших фактов и уже совпавших временных фактов. Нельзя повысить temporal только удалением трудных фактов. Precision и grounding допускают максимум0.02 снижения. На стресс-срезе также есть ограничения. Если выигрыш не подтверждён либо страховочный набор ухудшился/не проверен полностью, экспортируется исходный +500. Новые чекпоинты остаются на Drive для анализа. Эти ограничения защищают наблюдаемое качество на наших внутренних данных, **не гарантируют отсутствие ухудшения на неизвестном тесте**.

Синтетические и реальные метрики показываются отдельно: лёгкие синтетические примеры не могут скрыть снижение на реальных звонках. Страховочный набор участвует в откате, поэтому он не называется независимым финальным тестом. Последняя независимая оценка — официальный val383.

## Время и ячейки

Откройте MTS_11_Qwen06_Temporal_SFT.ipynb, выберите A100. Запускайте1→2→3→4→5. Ячейка4 действительно обучает. Сам цикл имеет предел90 минут; это верхний предел, а не обязательное время ожидания. При завершении одного прохода он остановится раньше. Загрузка, проверки и оценка идут дополнительно.

Общий бюджет пакета —300 минут от первой ячейки, включая будущую официальную оценку. Обучающий этап ограничен180 минутами общего времени; точное обучение90 минутами. Конечный абсолютный предел —16 ноября06:15 МСК, чтобы оставить резерв до08:00. Эти ограничения не являются обещанием доступности Colab или его квоты. При реальном меньшем остатке ресурсов уменьшитеTOTAL_MINUTES до начала нового запуска.

Ячейка6 по умолчанию отключена. После анализа результата её можно включить для выбранной версии: три режима FP16/INT8/INT4 на одинаковых4 звонках, затем383 val. Используется остаток общего300-минутного бюджета, он не сбрасывается. При нехватке времени сохраняется частичная оценка без заявления о прохождении порога.

## Какой ZIP загрузить

**Лёгкий** mts_qwen06_temporal_v23_light.zip содержит код и данные. Он автоматически восстановит +500 из уже загруженного v21 ZIP по пути/content/mts_v22_uploads либо из папки предыдущего MTS_10 на Drive. Все файлы проверяются по хешам; +250 не принимается вместо +500.

**Полный** mts_qwen06_temporal_v23_full.zip дополнительно содержит адаптер +500 и tokenizer, поэтому подходит для чистой среды без прежних файлов. Базовые веса Qwen в него не входят — они загрузятся из HF по фиксированной revision. Для ячейки2 достаточно одного из этих ZIP. Если лёгкий не нашёл родителя, загрузите полный; не начинайте обучение со случайного адаптера.

## Чекпоинты и результат

На Drive создаётся MyDrive/MTS_Qwen06_Temporal_runs/temporal_TIMESTAMP. Полные checkpoint со state оптимизатора сохраняются на шагах0,16 и далее каждые32 обновления. Дообучение возобновляется только с последнего полного checkpoint этого же запуска. Смена зависимостей/конфигурации не выдаётся за точное продолжение. Начало бюджетного отсчёта сохраняется.

После завершения автоматически создаются два ZIP на Drive: небольшой*_results.zip для анализа и*_model.zip с выбранным export для разработчика. Автоматически скачивается только небольшой отчёт, чтобы не повторять медленную передачу больших весов. Состояние оптимизатора остаётся на Drive в checkpoints; маленький отчёт его не содержит.

В experiment_report.json смотрите selected_updates и selected_original_parent. При selected_updates=0 новой версии не удалось безопасно улучшить исходную. Статус completed означает завершение процесса, а не прохождение хакатонных порогов. Для реального сервиса используйте serving-метрики, не показатели всех кандидатов до фильтра договорённостей.

Порог рассмотрения temporal≈0.4206, рабочая цель≥0.44. Качество на официальном наборе и ресурсное превосходство относительно большого baseline ещё не доказаны.

## Источники и пределы проверки

Frozen prepared v3 + официальный evaluator2.1/catalog без изменений. Детали состава: audit/data_policy.json, split_ids.json, examples.json; recipe сохранён как читаемый архивный исходник с исходными workspace-путями.
